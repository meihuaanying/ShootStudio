## 0. 研究结论与可达性实测（本机）

| 源 | 状态 | 用途 |
|---|---|---|
| Pexels API + images.pexels.com | ✅ 200 | 器材/服装实拍、电影感实拍（运行时可抓，工作区缓存） |
| image.tmdb.org（图片 CDN） | ✅ 200 | 剧照/静帧图片直链可用（即使 API 被墙） |
| api.themoviedb.org | ❌ 000 | 剧照检索；需代理或构建期清单 |
| upload.wikimedia.org / Openverse / archive.org / FILMGRAB / Bangumi | ❌ 000 | 需代理后可用 |
| poly.pizza + static.poly.pizza（GLB 直链） | ✅ 200 | Quaternius CC0 3D 人物/服装/发型 |
| raw.githubusercontent / cdn.jsdelivr | ✅ 200 | three addons 与开源数据镜像 |

**关键法律结论**：有版权的影视/动漫静帧**不得随安装包分发**（"风险自负"不能豁免分发者）。合法方案 = ① 已验证公有领域（PD）影片静帧包；② "我的素材包"目录（用户自放素材，启动索引，包体不含侵权内容）；③ 运行时抓取（TMDB/FILMGRAB，用户授权 + 代理）；④ Pexels 实拍仅作"实拍氛围参考"明确标注，不冒充剧照。

**技术结论**：three r169 本地已有 `GLTFLoader/SkeletonUtils` 示例（web/node_modules，可 vendor 进引擎包）；SkeletonUtils.retarget 支持骨骼映射；Quaternius 人形骨骼可用 12 关节语义驱动；低多边形风格（非写实照片级）经用户确认接受。

## 2. 硬规则（V3 增补，违反即返工）

- **R11 版权红线**：仓库/安装包不得包含有版权的影视、动漫、厂商产品图；所有内置图片必须为 PD/CC0/CC-BY 或程序生成，并在 `attribution.json` 登记。
- **R12 溯源与标注**：每张实拍/剧照在 UI 上可见来源与许可（或"示意图/氛围参考"标注）；无来源时显示空态与配置引导，不得以假图填充。
- **R13 代理优先**：所有被墙源必须走统一代理层；代理未配置时给出可执行的引导（设置入口一键跳转），不得静默空白。
- **R14 秘钥处理**：内置默认凭据可一键清空/替换；日志与错误信息不得输出完整 Key；导出/公告不得包含 Key。
- **R15 人物资产契约**：引擎必须加载 GLB + 骨骼；若加载失败，UI 明确报错并保留上次可用模型，**禁止静默退回程序假人**（允许用户手动切换"轻量模式"）。
- **R16 姿势校对**：每条姿势的 GLB 渲染截图入库（docs/pose-qa/），人工抽查 + 至少 12 条进入 golden；标题与关节语义不一致的姿势不得上架。
- **R17 包体预算**：安装包 ≤150MB；GLB 人物/服装合计 ≤40MB；图片运行时缓存不打包。

## 3. 交付清单（可测量）

### A. 画面参考（P1）
- A1 PD 静帧包：`tool/gen_pd_stills.dart`（构建期抓取，代理/直连两种模式）+ `assets/content/stills/pd/*.jpg` + 来源与 PD 证明链接；≥8 部影片 × 4–6 帧。
- A2 「我的素材包」目录：设置页可见路径 + 一键打开；启动时索引（图片→色卡→库条目）；支持放置剧照/动漫截图。
- A3 导入工作流：Ctrl+V 粘贴、拖拽、文件夹监看（watch 指定目录，增量导入）。
- A4 TMDB 检索面板：电影/剧集/动画搜索（中英）；影片页展示真实剧照/分集静帧网格；一键入画板（记录 TMDB 署名与"TMDB 未背书"声明）。
- A5 FILMGRAB 面板保留：可达时正常；不可达时提示代理。
- A6 Pexels 电影感实拍入口：中文/英文关键词（复用翻译表）→ 结果网格（明确标注"实拍氛围参考"）→ 入画板。
- A7 空态与来源标注：所有卡片显示 来源/许可/是否为剧照；不得出现无来源的纯色块。

### B. 3D 人物与换装（P2）
- B1 资产管线：`tool/gen_characters.dart`（poly.pizza/static 直链，校验页面上许可字段）→ `assets/models/characters/*.glb` + attribution。
- B2 引擎：GLTFLoader + SkeletonUtils + AnimationMixer 就绪；加载进度与失败提示；drawcall/内存预算记录。
- B3 换人：≥6 个可选人物（男女/体型），切换动画；肤色/发色（材质变体）。
- B4 换装：≥8 套服饰（含休闲/职业/运动/奇幻），一键切换 + 颜色变体；汉服/婚纱/JK 近似套标注"示意图"。
- B5 姿势驱动：12 关节→骨骼映射表（每骨骼轴向校准）；默认站姿、蹲/坐/躺/跪/动态均达到"可作摄影参考"的解剖可信度；照片角度的关节限制（防反关节）。
- B6 布光联动：换装/换人后灯光预览同步；轻量模式开关（保留程序假人作为"轻量模式"显式选项）。

### C. 姿势库重组（P3）
- C1 `tool/GEN_POSES_V3`：以 GLB 可表达范围重建；数量 120–150（质量优先），分类：站/坐/蹲/跪/靠/躺/动态/手部/神态/道具互动。
- C2 校对：`tool/pose_qa.mjs`（Edge headless 渲染每条姿势的 4 视角缩略图）→ docs/pose-qa/ + 人工抽查清单；≥12 条 golden。
- C3 元数据：每条含 镜头/机位/要领/常见错误/难度/适合场景（单人/双人提示）。
- C4 标题一致性硬校验：名称动作词必须在关节数据中可验证（回眸→neck ry、插兜→elbow、跳→rootY 等）；测试守护。

### D. 器材与服装实拍（P4）
- D1 器材实拍：`tool/gen_gear_photos.dart` 用内置 Pexels Key 按型号/品类抓图缓存到 `assets/content/gear/photo/`（每类目/品牌代表性图），标注"氛围实拍/非官方"；卡片优先实拍，缺图回落插画（标注）。
- D2 型号导入：设置页指定"器材图目录"，按 `型号.jpg|png` 自动匹配 493 条器材。
- D3 代理可达时：Wikimedia 产品图优先抓取并署名。
- D4 服装参考：9 类目各 6–12 张 Pexels 实拍缓存 + 来源；展示在服装目录卡片。
- D5 许可页：attribution 全量（Pexels 摄影师、TMDB、Quaternius、PD 影片来源）。

### E. 官网互动（P5）

## 6. 反模式（出现即返工）

- 用渐变色卡/插画冒充剧照或实拍；实拍图不标来源/许可。
- 3D 加载失败静默退回假人；姿势标题与渲染动作不符。
- 内置任何有版权影视/动漫/厂商图。
- 代理未配置时静默空白而非引导。
- 把 Key 写进日志/公告/导出包。
- 姿势数量虚报（未逐条校对即宣称"全部达标"）。
