# V8.6 / P3：首屏图宽达标（D157 ≥50% 视口宽）+ 把这条合同条款接进 CI

本阶段是 V8 清理线（P0 → P3）的最后一阶段。tag 继续用 `v8.x` 而非新起 `v9.x`：
P3 属同一条清理线，一个阶段一个 tag，不另开版本号。

## 1. 合同条款 vs 实测：条款写了，没人验，于是长期不达标

合同 §5 首页条款（D157）：

> 首屏 = 真实产品静帧/截图大图（**≥50% 视口宽**）+ 衬线大标题 + 双下载 CTA

而 V8.6 之前的实测（`web/tool/hero_probe.mjs` 探针，量的是 `<img>` 的实际渲染盒）：

| 视口 | 旧图宽 | 旧占比 | 达标？ |
|---|---|---|---|
| 1024×768 | 499.1px | 48.74% | ✗ |
| 1280×800 | 637.4px | **49.79%** | ✗（差 0.21pp） |
| 1920×1080 | 637.4px | **33.2%** | ✗（差 16.8pp） |
| 2560×1440 | 637.4px | 24.9% | ✗（差 25.1pp） |

**条款写着 ≥50%，实际从 1280 往上全线不达标，而且差得越来越离谱 —— 因为没有任何门禁在守它。**
`shot_s10.mjs` 只截 30 张图给人看，**不量任何宽度**。这就是 R82 点名的反模式：
「条款写了但没人验」等价于「条款不存在」，且它在 CI 全绿的情况下长期存在。

## 2. 根因：容器封顶把图宽钉死

`web/src/pages/index.astro` 的 hero 栅格：

```
max-w-[1280px]  ... lg:grid-cols-[minmax(0,0.92fr)_minmax(0,1.08fr)]
```

1.128 与 0.92 的和是 2，所以图片列占 1.08/2 = 54% 的**栅格内容宽**；
而栅格内容在 1280 封顶后是固定的 1184px —— 扣掉 px-6(48) 与 gap-12(48)：

- 图列宽 = (1184 − 48) × 54% = **637.4px，与视口无关**
- 于是视口越大占比越低：1280 → 49.79%，1920 → 33.2%

即：**图宽是常数，视口是变量，占比必然随视口单调下滑。** 1280 档只差 0.21pp
纯属巧合（0.92/1.08 这个比例把 1280 视口刚好卡在边界上），不是设计对齐。

## 3. 方案选择：为什么不让 hero 通栏（也记下被否掉的方案）

直觉修法是「把 `max-w-[1280px]` 放宽」——但实测推演显示它会把页面搞难看：

- 容器放宽到 1920 后，1920 视口下栅格内容左边缘变成 **x=24**（px-6），
  而页面其它所有 section 的左边缘在 **x=344**（(1920−1280)/2 + 24）。
  首屏文字会贴着屏幕左缘、与下方「四步工作流」等区块错开 320px —— 一眼就是坏版面。
- 折中（放宽到 1600）仍有 160px 错位，且要同步改栅格比例才能勉强过线，收益不明。

**选定方案：文字列严格守住站点 1280 栅格（左边缘一个像素都不动），只让首屏图向右出血。**
这样「全站左对齐」这个既有版面纪律不被破坏，而图片拿到 ≥50% 视口宽。
出血到接近视口右缘，也正好是杂志式首屏的常见做法，观感上是刻意的而非溢出。

### 实现（两处，`web/src/pages/index.astro`）

1. 栅格比例 `0.92fr / 1.08fr` → `0.88fr / 1.12fr`（图片列拿到 56%，左起点左移约 20px）；
2. `figure.shot` 加 `lg:!w-[51vw]`。

第 2 点必须用 Tailwind 的 `!` 前缀：`.shot` 类在 `global.css` 里 `@apply ... w-full`，
不带 `!` 的话 `w-full` 会把宽度按回 100%（= 图列宽），改动静默失效。

### 为什么是 51vw，以及越界风险（这条最关键）

`html, body` 上有 `overflow-x: hidden` —— **图片一旦越出视口右缘，会被静默裁掉：
不报错、不出滚动条、只是图少了一块**。所以宽度取值必须留出右缘余量，且余量只能靠实测量。

图片右缘 = 左起点 + 图宽。左起点在 1024 档最小视口下约 480px（0.88/1.12 之后），
所以 51vw 在该档只余约 22px。取 52vw 余量会被压到约 11px，太薄；再宽就越界裁图。
**51vw 是「占比稳过 50% + 各档右缘余量 ≥22px」的取值。**

这也直接决定了门禁的判据：**必须单独查图片右缘，不能只查 `document.scrollWidth`** ——
后者在 `overflow-x: hidden` 下永远是 0，越界是查不出来的（图已经没了）。

## 4. 新门禁：`web/tool/hero_gate.mjs`（入 CI）

`shot_s10.mjs` 的定位是「截图给人看」，不该塞判据；故新写一条独立门禁，
挂进 `.github/workflows/ci.yml` 的 `website-gate` job（截图门禁之后、证据校验之前）。

判据（4 个视口 × 4 条，全过才 PASS，exit 0）：

| 判据 | 说明 |
|---|---|
| 首屏图存在且已加载 | `complete === true && naturalWidth > 0` —— 图没加载完就没有尺寸可言，先排掉这种假绿 |
| 图宽 ≥ 50% 视口宽 | 按合同字面口径量 **`<img>` 的渲染盒**，不是量容器/栅格 |
| 图未被裁（右缘在视口内） | 直接查 `img.getBoundingClientRect().right <= innerWidth` —— 理由见 §3 |
| 文档无横向溢出 | `scrollWidth <= innerWidth`，别把整页拱出横向滚动 |

视口取 `1024×768`（lg 断点下界，越界风险最大的一档）、`1280×800` 与 `1920×1080`
（与截图门禁一致的两档）、`2560×1440`（最宽档，封顶失效类改动在这里现形）。
手持档 390×844 不在范围：该档首屏单列堆叠，图宽天然 100%。

证据写入 `docs/qa/v8-6-hero-width-gate.json`（含每个视口的实测值），并**入库** ——
`website-gate` job 的既有约定就是「证据落在 git 里」（它最后一步 `Verify evidence
landed in git` 就是在查这个）。

## 5. 反向验证：证明门禁不是装饰

把 `index.astro` 换回 HEAD 版（旧栅格 + 无 51vw），重建后跑门禁；再还原新版重建跑。
全过程用脚本做，换入换出按字节比对（6015 bytes 原样归还）：

```
[旧版布局 期望FAIL] gate rc=1
    FAIL 1024x768  图宽 >= 50% 视口宽 :: 48.74% (imgW=499.1 / vw=1024)
    FAIL 1280x800  图宽 >= 50% 视口宽 :: 49.79% (imgW=637.4 / vw=1280)
    FAIL 1920x1080 图宽 >= 50% 视口宽 :: 33.2%  (imgW=637.4 / vw=1920)
    FAIL 2560x1440 图宽 >= 50% 视口宽 :: 24.9%  (imgW=637.4 / vw=2560)
    [hero-gate] FAIL (4)
[新版布局 期望PASS] gate rc=0
    PASS 1024x768  图宽 >= 50% 视口宽 :: 50.8%  (imgW=520.2  / vw=1024)
    PASS 1280x800  图宽 >= 50% 视口宽 :: 50.84% (imgW=650.8  / vw=1280)
    PASS 1920x1080 图宽 >= 50% 视口宽 :: 50.9%  (imgW=977.2  / vw=1920)
    PASS 2560x1440 图宽 >= 50% 视口宽 :: 50.92% (imgW=1303.6 / vw=2560)
    [hero-gate] PASS
旧版 rc=1（期望 1）／新版 rc=0（期望 0）→ OK：门禁确实抓得住旧布局
```

一红一绿，且红的是「旧布局」这个真实不达标态 —— 与 V8.5 引擎门禁同样的验证手法。

## 6. 影响面自查

- **截图门禁重跑：30/30 写出**，`announcements` 通道读数不变
  （`winVer/andVer` 均 2.0.0，双平台镜像 URL 与 SHA 占位文本一致）。

  说明栅格比例调整没有外溢到任何其它页面或档位。

## 8. 结论

D157 的「≥50% 视口宽」从「写了没人验、且长期不达标」变成「实测达标（50.8%~50.92%）
且 CI 会红」。改动只有两处 CSS 类，但配套做了三件事才算真的收口：
反证门禁抓得住旧布局、确认改动没外溢到其它 26 张截图、把「右缘是否被裁」单独设判据
（因为 `overflow-x: hidden` 会把越界静默吃掉）。
